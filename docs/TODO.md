## 🚀 Релиз v5.0.0 (Enterprise Core & Telemetry Redesign)

### Backend, ORM & Архитектура
- [x] **Миграция на Django ORM**: отказ от статических файлов конфигурации и переход на реляционные модели (`Cluster`, `Switch`, `OltDevice`, `Incident`).
- [x] **Гибридное ядро FastAPI + Django ASGI**: запуск асинхронного движка опроса (FastAPI/WebSocket) и панели администрирования (Django WSGI) в рамках единого процесса через `WSGIMiddleware`.
- [x] **Инвентарь через Django Admin**: полноценный UI для управления узлами, кластерами и OLT по адресу `/admin/` с валидацией данных.
- [x] **Автоматическая инициализация**: применение миграций и создание суперпользователя на основе переменных окружения (`.env`) при старте контейнера.
- [x] **Гибридный опрос L2 (SNMP + Ping fallback)**: автоматическая проверка хоста через ICMP при зависании SNMP-демона устройства (узел маркируется статусом `PING` вместо ложного `DOWN`).
- [x] **Оптимизация работы с базой**: изоляция подключений через `close_old_connections` для предотвращения блокировок SQLite (`database is locked`) в параллельных воркерах.
- [x] **Очистка системных дескрипторов**: функция нормализации названий моделей коммутаторов с фильтрацией технического мусора из ответов `sysDescr`.

### Безопасность и Сессии
- [x] **Долгоживущие сессии**: переход на авторизацию через пользователей Django с генерацией JWT-токенов со сроком действия 365 дней (исключены внезапные сбросы сессий в 00:00).
- [x] **Сквозная защита эндпоинтов**: валидация заголовков `Authorization: Bearer <token>` на всех маршрутах API (`/api/*`) и защищенном WebSocket (`/ws`).
- [x] **Клиентская защита (`security.js`)**: блокировка контекстного меню, вызова DevTools (F12, комбинации клавиш инспектора) и активная задержка отладки.

### Frontend, UI & UX

## 📦 Ранее реализовано (v1.0.0 — v4.0.0)

### Мониторинг GPON & Коммутаторов
- [x] Клиент Netmiko с поддержкой шасси ZTE ZXA10 C300, C320, C600, C650.
- [x] Автоматический сбор связок порт-договор (`detail-info` на C300 и `User-Defined-Rid` на C600).
- [x] Интеллектуальное разделение аварий на физический обрыв кабеля (`LOS`) и затухание/изгиб патчкорда (`LOSi`).
- [x] Фильтрация некорректных дат прошивок OLT (`0000-00-00 00:00:00`).
- [x] Асинхронный SNMPv2-поллер на базе единого глобального движка `SnmpEngine`.
- [x] Детекция массовых аварий (>60% потерь на порту OLT или в кластере коммутаторов).
- [x] Серверный аналитический движок «Ночного аудита» (`audit_engine.py`) для отчетов по сменам (17:00–09:00 и суточных).
- [x] Алгоритм кластеризации кратковременного дребезга линий (флаппинга) в рамках часового интервала.

### Клиентский интерфейс & Реактивность
- [x] Микро-компонентная архитектура на Svelte 4 + TailwindCSS.
- [x] Реактивные хранилища данных (`networkStore.js`, `themeStore.js`, `notificationStore.js`).
- [x] Плавающий HUD-индикатор фонового опроса сети (`PollingHud.svelte`) со шкалой 0–100%.
- [x] Мгновенная инициализация интерфейса из предзагрузочного кэша LocalStorage (0 сек задержки при старте).
- [x] Умный переход по номеру договора или IP из строки поиска с раскрытием нужной OLT и платы.
- [x] Экспорт списка абонентов конкретного порта в файл формата CSV.
- [x] Динамический таймер обратного отсчета до следующего цикла авто-опроса сети.
- [x] Всплывающие Push-уведомления (Browser Notification API) об авариях и восстановлениях узлов.

- [x] Хранение постоянных данных и SQLite БД через volume-маппинг (`./backend/data`).
