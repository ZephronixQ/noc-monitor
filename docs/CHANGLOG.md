## [2.2.0] — 2026-04-09

Обновление логики парсинга GPON, внедрение продвинутого авто-поиска и полная реструктуризация Docker-развертывания для работы на белом (публичном) IP-адресе.

### Added
- **Детекция LOSi** — бэкенд теперь анализирует таблицу `show gpon onu detail-info` и разделяет аппаратный обрыв линии (`LOS`) и проблемы на стороне абонента (`LOSi`, например, выключенный терминал или согнутый патчкорд).
- **Умный глобальный поиск** — при вводе номера договора в строку поиска система автоматически переключает левое меню на нужную OLT, раскрывает нужный порт, перелистывает страницу и включает фильтр группы, в которой находится клиент.
- **Индикация LOSi в UI** — пурпурный цвет (Fuchsia) для статусов `LOSi`, раздельные счетчики на дашборде, в бейджах левого меню и внутри портов.
- **Новый фильтр** — добавлена кнопка «ТОЛЬКО LOSi» для изолированного просмотра клиентских проблем.
- **Nginx Reverse Proxy** — добавлен отдельный файл `nginx.conf` для фронтенда. Nginx теперь проксирует запросы `/api/` и WebSocket `/ws` на бэкенд, работая как единая точка входа.

### Changed
- **Архитектура Docker Compose** — бэкенд больше не "торчит" наружу портом `8000`. Внедрена внутренняя сеть `internal` (bridge). Весь трафик идет через Nginx (порт 80), что решает проблемы с CORS и позволяет легко повесить систему на белый IP.
- Логика парсинга ZTE OLT: регулярное выражение теперь ищет только реальные даты (20xx-...), игнорируя баги прошивки с записями `0000-00-00 00:00:00`.
- Убрана жесткая привязка к `localhost` и `window.location.hostname` в `App.svelte` (закомментированы переменные `host`), запросы идут по относительным путям через Nginx.
- График на главном экране теперь агрегирует общие потери на сети (сумма `LOS` и `LOSi`).
- Система Push-уведомлений и алертов теперь реагирует на появление статуса `LOSi` так же, как и на обычный обрыв.

## [2.1.0] — 2026-04-08

Масштабное обновление интерфейса мониторинга: внедрена интерактивная система уведомлений и продвинутая фильтрация здоровых узлов.

### Added
- **Кнопка принудительного обновления** — возможность сбросить таймер и запустить опрос OLT вне очереди (на бэкенде реализовано через прерывание `asyncio.Event`).
- **Индивидуальные Push-уведомления** — браузерные оповещения не только о массовых авариях, но и о падении/восстановлении конкретных коммутаторов и обрывах оптики (LOS) у клиентов GPON.
- **Панель истории уведомлений** — иконка "колокольчик" с индикатором непрочитанных событий. Хранит хронологию инцидентов с цветовым кодированием.
- **Счетчики в боковом меню** — вывод количества аварий прямо в кнопках выбора OLT и локаций коммутаторов.

### Changed
- **Умная фильтрация «Только LOS»** — теперь при включении фильтра из левого меню полностью скрываются те OLT и папки коммутаторов, на которых нет ни одной проблемы.
- **Анти-спам уведомлений** — система игнорирует статусы `DyingGasp` и `Offline` для индивидуальных оповещений клиентов GPON.

## [2.0.0] — 2026-04-07

Финальный релиз **noc-monitor**. Система переведена на полностью контейнерное развёртывание, устранены проблемы производительности.

### Added
- **Docker Compose** — одной командой (`docker compose up -d`) поднимается весь стек: Backend + Frontend
- `Dockerfile.backend` и `Dockerfile.frontend` — полностью автономные образы без внешних зависимостей
- Volume-маппинг `./backend/data:/app/backend/data` — JSON-база истории сохраняется на хосте.

### Changed
- `poll_switches_loop` вызывает `save_json_db()` только при реальных изменениях.
- SNMP-движок переведён на один глобальный `SnmpEngine` — устранено зависание Event Loop.

### Fixed
- Зависание сервера при массовом опросе коммутаторов (Event Loop Death).
- Запрос истории прерывается (`AbortController`) при закрытии модалки до завершения загрузки.
