# Changelog

Все значимые изменения проекта фиксируются в данном файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).

## [5.0.2] — 2026-09-07

Хотфикс базы данных, подсистемы сохранения контрактов и алгоритма дребезга для оптического сегмента GPON.

### Added
- **Поле `contract` в модели `Incident`**: Договоры и описания абонентов теперь сохраняются в реляционную таблицу SQLite намертво при возникновении аварии. Договор больше не стирается, если абонент перешёл из `LOS` в `working` или `Logging`.
- **Детекция дребезга (Flapping) для GPON**: В модуль «Ночного аудита» внедрена полноценная группировка многократных падений абонентских терминалов за смену (`⚠️ ДРЕБЕЗГ: N СБОЕВ`) с разворачиваемой хронологией каждого микро-сбоя.
- **Страйки коммутаторов (SNMP)**: Внедрён фильтр отсечения ложных аварий — хост падает в `DOWN` строго после 7 пропусков подряд, но восстанавливается в `UP` моментально при первом же успешном ответе.

### Fixed
- **Ликвидация ложной суммаризации**: Исправлен эндпоинт `/api/history/{target_id}`, где поиск по подстроке `icontains` склеивал в одну карточку события разных абонентов с похожими номерами ONU.
- **Корректное завершение аварий**: Устранена проблема, из-за которой закрытые аварии продолжали отображаться со статусом `(Активен)` в Ночном аудите.

## [5.0.1] — 2026-09-07

Хотфикс кроссплатформенного запуска, автономной инициализации суперпользователя и генерации ключей безопасности.

### Added
- **Автоматическая синхронизация пользователя из `.env`**: Логика создания и обновления суперпользователя встроена в функцию `lifespan` ASGI-приложения (`asgi.py`). При первом старте контейнер автоматически активирует учётную запись (`is_active=True`, `is_staff=True`) и синхронизирует пароль из переменной `DJANGO_ADMIN_PASSWORD`.
- **Генератор криптографического секрета**: В документацию (`README.md` и `manual-setup.md`) добавлена однострочная команда на Python для генерации безопасного `DJANGO_SECRET_KEY` через модуль `secrets`.

## [5.0.0] — 2026-09-07

Юбилейный мажорный релиз: полный переход на реляционный инвентарь Django ORM, гибридный стек FastAPI + Django Admin, гибридный L2-поллер (SNMP + Ping fallback) и глубокий редизайн интерфейса.

### ⚠️ Breaking Changes
- **Отказ от статического `inventory.py`:** Конфигурационные файлы `SWITCH_LIST` и `OLT_DEVICES` полностью удалены. Инвентарь теперь хранится в моделях Django (`Cluster`, `Switch`, `OltDevice`, `Incident`).
- **Смена схемы аутентификации:** Ежедневный пароль смены заменён на стандартные учётные записи операторов Django с выдачей долгоживущего JWT-токена (365 дней).
- **Единый порт развертывания:** Бэкенд и админка работают внутри одного ASGI-процесса. Django Admin доступен по пути `/admin/` через единую точку входа Nginx.

### Added
- **Гибридный статус коммутаторов (SNMP + ICMP Ping fallback):** Модуль `poller/snmp.py` проверяет хост через SNMP, а в случае недоступности демона — выполняет асинхронный ICMP-пинг. Узел помечается бейджем `PING` вместо ложного падения в `DOWN`.
- **Интеграция Django Admin в FastAPI:** Через `starlette.middleware.wsgi.WSGIMiddleware` панель администрирования Django встроена непосредственно в FastAPI-приложение со статикой `/static/admin/`.
- **Сплит-дашборд 3/10 + 7/10:**
  - Левая колонка: телеметрия флота GPON, кольцевой SVG-индикатор доступности с сегментацией по типам деградаций, спектр-бар аномалий.
  - Правая колонка: оперативная матрица инцидентов в реальном времени с синхронизированными группами коммутаторов и оптических плат.
- **Двухсегментные и спектральные прогресс-бары:** Индикаторы без пустых зон — точная визуализация соотношения Online / Down / LOS / LOSi / DyingGasp / Offline.
- **Годовой срок действия токена:** Операторам больше не требуется проходить повторную авторизацию каждые сутки в 00:00.
- **Авто-создание суперпользователя:** При первом старте контейнера скрипт автоматически генерирует пользователя `admin` с параметрами из `.env`.

### Changed
- **Оптимизация базы данных:** Таблица `incidents` управляется через Django ORM с индексами на `target_id`, `start_time` и `end_time`. Применено автоматическое закрытие старых соединений (`close_old_connections`) для защиты от блокировок в асинхронных задачах.
- **Редизайн «Ночного аудита»:** Чистый интерфейс списков инцидентов в светлой теме, четкие акцентные рамки карточек, раздельные блоки для аварий головных OLT и обрывов клиентских кабелей.
- **Парсер моделей коммутаторов:** Функция очистки строк `clean_model_name` убирает системный мусор из ответов `sysDescr`.

### Fixed
- Устранена проблема дублирования счетчиков потерь в тулбарах GPON и L2.
- Исправлено поведение клавиши `ESC`: теперь закрытие модального окна истории узла перехватывается с `stopImmediatePropagation` и не сбрасывает состояние страницы позади окна.
- Устранена ошибка утечки памяти при удержании соединений SQLite в многопоточном цикле опроса.

## [4.0.0] — 2026-08-05

Мажорный релиз с фундаментальным обновлением подсистемы безопасности, авторизацией роутов, внедрением центра управления сессиями, серверного движка «Ночного аудита» и микро-компонентной архитектурой UI.

### ⚠️ Breaking Changes
- **Обязательная авторизация API:** Все маршруты бэкенда `/api/*` и WebSocket `/ws` закрыты требованиями Bearer JWT-токенов (`require_auth`). Неавторизованные запросы возвращают `401 Unauthorized`.

### Added
- **Система аутентификации и динамических паролей:** Добавлен модуль `utils/auth.py`. Вход в систему осуществляется по динамическому паролю, меняющемуся каждые сутки (`DDMMYYYY`).
- **Защита от брутфорса и авто-бан IP:** Автоматическая блокировка IP-адреса на 24 часа при превышении 3 попыток ввода пароля.
- **Панель управления сессиями (`/sessions`):** Скрытый интерфейс администрирования для просмотра активных сессий, логов аудита, ручной блокировки/разблокировки IP и принудительного разрыва сессий (Session Kill).
- **Серверный движок Ночного Аудита (`audit_engine.py`):** Формирование отчётов смен перенесено на бэкенд (SQL-запросы к SQLite), с полным отсечением статусов `LOSi` из суточной статистики обрывов.
- **Виджет Polling HUD (`PollingHud.svelte`):** Плавающий индикатор прогресса (0–100%) с детализацией текущих шагов при запуске принудительного сканирования OLT.
- **Защита клиентского кода (`security.js`):** Запрет вызова контекстного меню, блокировка клавиш F12, Ctrl+Shift+I/J/C, Ctrl+U/S и активный зацикленный отладчик.
- **Предзагрузочный кэш сети:** Мгновенное отображение последнего состояния дашборда из LocalStorage до завершения запроса к API.

### Changed
- **Декомпозиция фронтенда:** Табы монолита разделены на микро-компоненты: `SwitchCard`, `SwitchSidebar`, `SwitchToolbar`, `GponPortCard`, `GponToolbar`, `GponOnuTable`, `DashboardAnomalies`.

### Fixed
- **Очистка дубликатов в логах:** Устранены ошибки дублирования записей при частых колебаниях статусов (флаппинге) на портах GPON.
- **Стабильность базы данных:** Предотвращены блокировки SQLite при параллельном вызове аудита и записи событий опроса.

## [3.0.0] — 2026-07-10

Глобальное обновление архитектуры full-stack приложения: переход с файловой JSON-хранилища на реляционную СУБД SQLite, поддержка гетерогенного парка OLT (включая платформы ZTE C600), декомпозиция фронтенда на независимые Svelte-хранилища (stores) и внедрение модуля аналитики «Ночной аудит».

### Added
- **Модуль «Ночной аудит» (Night Audit)** — новый раздел интерфейса с интерактивной сеткой календаря, отображающий дни с зафиксированными инцидентами. Добавлена фильтрация по рабочим сменам (ночная смена с 17:00 до 09:00 и полные сутки).
- **Алгоритм кластеризации дребезга (Flapping)** — система автоматически объединяет каскад кратковременных падений одного хоста в рамках одного часа в единый групповой инцидент с разворачиваемой хронологией событий.
- **Поддержка ZTE C600** — реализован специализированный клиент опроса OLT серии C600, обрабатывающий виртуальные порты (`show port-identification port vport-...`) для извлечения параметров авторизации абонентов (User-Defined-Rid).
- **Миграция на SQLite** — база данных переведена на реляционную СУБД SQLite. Реализована автоматическая инициализация структуры таблиц, индексация ключевых полей для быстрого поиска по большим массивам данных и механизм безопасной многопоточной записи с использованием блокировок (`threading.Lock`).
- **Модульная архитектура Svelte** — монолитное клиентское приложение разделено на специализированные компоненты и реактивные хранилища:
  - `themeStore.js` — управление цветовым оформлением.
  - `networkStore.js` — менеджер сетевых запросов, автоматический расчет общей статистики и WebSocket-соединения.
  - `notificationStore.js` — централизованная обработка дельты изменений сетевого статуса и генерация уведомлений.

### Changed
- **Конфигурация инвентаря** — список опроса OLT переведен с формата простых IP-строк (`OLT_LIST`) на расширенные профили настроек (`OLT_DEVICES`), позволяющие указывать индивидуальные порты, типы шасси (`c300`/`c600`) и параметры авторизации.
- **Оптимизация рендеринга таблиц** — для длинных списков ONU добавлена локальная пагинация (по 20 записей на страницу) с функциями сортировки по идентификатору, адресу, статусу и длительности простоя.
- **Дизайн светлой темы** — устранены высококонтрастные грязные фоновые оттенки в таблицах и карточках, они заменены на мягкие градиенты и светлые тона.
- **Плавное позиционирование UI** — при раскрытии информации о плате OLT добавлена плавная прокрутка (`scrollIntoView`) для автоматического центрирования таблицы абонентов на экране.

### Fixed
- **Устранение блокировок СУБД** — решена проблема конкурентного доступа к файлу базы данных при параллельном опросе («database is locked») за счет изоляции пишущих транзакций.
- **Автоматическая очистка кэша событий** — при инициализации приложения запускается процедура закрытия зависших аварий текущим временем и валидация некорректных записей в локальном кэше браузера.
- **Утечки памяти WebSocket** — улучшена обработка ошибок закрытия сокетов, предотвращающая зависание фоновых задач при обрыве связи со стороны клиента.

## [2.2.0] — 2026-04-09

Обновление логики парсинга GPON, внедрение продвинутого авто-поиска и полная реструктуризация Docker-развертывания для работы на белом (публичном) IP-адресе.

### Added
- **Детекция LOSi** — бэкенд теперь анализирует таблицу `show gpon onu detail-info` и разделяет аппаратный обрыв линии (`LOS`) и проблемы на стороне абонента (`LOSi`, например, выключенный терминал или согнутый патчкорд).
- **Умный глобальный поиск** — при вводе номера договора в строку поиска система автоматически переключает левое меню на нужную OLT, раскрывает нужный порт, перелистывает страницу и включает фильтр группы, в которой находится клиент.
- **Индикация LOSi в UI** — пурпурный цвет (Fuchsia) для статусов `LOSi`, раздельные счетчики на дашборде, в бейджах левого меню и внутри портов.
- **Новый фильтр** — добавлена кнопка «ТОЛЬКО LOSi» для изолированного просмотра клиентских проблем.
- **Nginx Reverse Proxy** — добавлен отдельный файл `nginx.conf` для фронтенда. Nginx теперь проксирует запросы `/api/` и WebSocket `/ws` на бэкенд, работая как единая точка входа.

### Changed
- **Архитектура Docker Compose** — бэкенд больше не "торчит" наружу портом `8000`. Внедрена внутренняя сеть `internal` (bridge). Весь трафик идет через Nginx (порт 80), что решает проблемы с CORS и позволяет легко повесить систему на белый IP.
- Логика парсинга ZTE OLT: регулярное выражение теперь ищет только реальные даты (20xx-...), игнорируя баги прошивки с записями `0000-00-00 00:00:00`.
- Убрана жесткая привязка к `localhost` и `window.location.hostname` в `App.svelte` (закомментированы переменные `host`), запросы идут по относительным путям через Nginx.
- График на главном экране теперь агрегирует общие потери на сети (сумма `LOS` и `LOSi`).
- Система Push-уведомлений и алертов теперь реагирует на появление статуса `LOSi` так же, как и на обычный обрыв.

## [2.1.0] — 2026-04-08

Масштабное обновление интерфейса мониторинга: внедрена интерактивная система уведомлений и продвинутая фильтрация здоровых узлов.

### Added
- **Кнопка принудительного обновления** — возможность сбросить таймер и запустить опрос OLT вне очереди (на бэкенде реализовано через прерывание `asyncio.Event`).
- **Индивидуальные Push-уведомления** — браузерные оповещения не только о массовых авариях, но и о падении/восстановлении конкретных коммутаторов и обрывах оптики (LOS) у клиентов GPON.
- **Панель истории уведомлений** — иконка "колокольчик" с индикатором непрочитанных событий. Хранит хронологию инцидентов с цветовым кодированием.
- **Счетчики в боковом меню** — вывод количества аварий прямо в кнопках выбора OLT и локаций коммутаторов.

### Changed
- **Умная фильтрация «Только LOS»** — теперь при включении фильтра из левого меню полностью скрываются те OLT и папки коммутаторов, на которых нет ни одной проблемы.
- **Анти-спам уведомлений** — система игнорирует статусы `DyingGasp` и `Offline` для индивидуальных оповещений клиентов GPON.

## [2.0.0] — 2026-04-07

Финальный релиз **noc-monitor**. Система переведена на полностью контейнерное развёртывание, устранены проблемы производительности.

### Added
- **Docker Compose** — одной командой (`docker compose up -d`) поднимается весь стек: Backend + Frontend
- `Dockerfile.backend` и `Dockerfile.frontend` — полностью автономные образы без внешних зависимостей
- Volume-маппинг `./backend/data:/app/backend/data` — JSON-база истории сохраняется на хосте.

### Changed
- `poll_switches_loop` вызывает `save_json_db()` только при реальных изменениях.
- SNMP-движок переведён на один глобальный `SnmpEngine` — устранено зависание Event Loop.

### Fixed
- Зависание сервера при массовом опросе коммутаторов (Event Loop Death).
- Запрос истории прерывается (`AbortController`) при закрытии модалки до завершения загрузки.
