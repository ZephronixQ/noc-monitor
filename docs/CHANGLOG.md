## [2.0.0] — 2026-04-07

Финальный релиз **noc-monitor**. Система переведена на полностью контейнерное развёртывание,
устранены все известные проблемы производительности.

### Added
- **Docker Compose** — одной командой (`docker compose up -d`) поднимается весь стек: Backend + Frontend
- `Dockerfile.backend` и `Dockerfile.frontend` — полностью автономные образы без внешних зависимостей
- Volume-маппинг `./backend/data:/app/backend/data` — JSON-база истории коммутаторов сохраняется на хосте и не теряется при пересборке контейнера

### Changed
- `poll_switches_loop` вызывает `save_json_db()` только при реальных изменениях (флаг `has_db_changes`) — лишние записи на диск исключены
- SNMP-движок переведён на один глобальный `SnmpEngine` — устранено зависание Event Loop при параллельных запросах

### Fixed
- Зависание сервера при массовом опросе коммутаторов (Event Loop Death)
- Модальное окно истории не открывалось повторно если предыдущий запрос ещё не завершился
- Запрос истории теперь прерывается (`AbortController`) при закрытии модалки до завершения загрузки
- Кеширование сломанных ответов браузером — добавлен `cache: 'no-store'`

## [1.0.1] — 2026-04-04

### Added
- Группировка коммутаторов по локациям (`SWITCH_GROUPS` в `inventory.py`) вместо плоского списка
- Папки/локации в UI — левая боковая панель с навигацией по группам коммутаторов
- Поиск по всем группам коммутаторов одновременно
- Табовый интерфейс: вкладки **ОБЗОР**, **GPON**, **КОММУТАТОРЫ**
- Вкладка **ОБЗОР** — сводная статистика: ONU онлайн/всего, коммутаторы Up/Down, количество OLT
- JSON EXPORT — выгрузка полного состояния системы одной кнопкой
- Отображение модели коммутатора и адреса объекта в одной строке (`Адрес | Модель`)

### Changed
- Цикл опроса разделён на два независимых:
  - OLT — раз в 30 минут (тяжёлый Telnet-опрос)
  - Коммутаторы — раз в 10 секунд (лёгкий SNMP)
- Интерфейс полностью переработан: вместо единого дашборда — три специализированные вкладки
- Карточки ONU в GPON-вкладке отображаются сеткой (5 колонок) вместо таблицы
- Убрана тёмная/светлая тема (единый светлый стиль)
- Убраны toast-уведомления и звуковые алерты

## [1.0.0] — 2026-04-04

Первый публичный релиз **noc-monitor** — fullstack-системы мониторинга GPON и коммутаторов.

### Backend
- FastAPI приложение с lifespan, CORS middleware и двумя endpoint'ами:
  - `GET /api/data` — первичная загрузка состояния
  - `WebSocket /ws` — live-обновления
- Асинхронный цикл опроса (`poll_devices_loop`) с интервалом 30 минут
- OLT-клиент (`olt_client.py`) на Netmiko + ThreadPoolExecutor:
  - Парсинг `show gpon onu state` (форматы A и B)
  - Автоматическое получение Description для ONU в статусах LOS / DyingGasp / Offline
- SNMP-клиент (`snmp_client.py`) на PySNMP asyncio:
  - GET `sysDescr` с timeout 2 с и 1 retry
  - Парсинг вендоров: ZTE ZXR10, SNR S-серии, D-Link DES/DGS, Eltex MES
- Парсеры (`utils/parser.py`):
  - `parse_onu_line` — разбор строк CLI ZTE OLT
  - `parse_sys_descr` — определение вендора и модели коммутатора по sysDescr
- WebSocket менеджер (`ws_manager.py`) с broadcast по всем активным соединениям
- Раздельные конфиги: `inventory.py` (оборудование, credentials) и `settings.py` (параметры, OID, паттерны)

### Frontend
- Svelte + Vite + Tailwind CSS
- Подключение к backend через REST (первичная загрузка) и WebSocket (live-обновления)
- Карточки устройств с цветными индикаторами статуса и счётчиками ONU
- Раскрывающиеся порты с фильтрацией по статусу (All / working / LOS / DyingGasp / Offline)
- Глобальный фильтр «Только аварийные» и поиск по интерфейсу / договору
- Пагинация: 16 портов на страницу, 50 ONU на страницу
- Экспорт состояния порта в CSV
- Таймер обратного отсчёта до следующего опроса
- Тёмная / светлая тема
- Toast-уведомления об обновлениях и ошибках
- Звуковые алерты при появлении аварий (Web Audio API)
- Метрики текущего устройства: всего / в работе / LOS / DyingGasp
